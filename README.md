# NetSwitch — 랜선 꽂아 둔 채로 인터넷 ↔ 업무망 전환

노트북 한 대로 **인터넷(와이파이)** 과 **업무망(유선 랜)** 을 번갈아 쓸 때,
랜선을 뽑았다 꽂는 대신 트레이 아이콘 더블클릭 한 번으로 전환합니다.
두 망이 동시에 연결되는 순간이 생기지 않도록 **항상 쓰던 쪽을 먼저 끊고 나서 다른 쪽을 연결**합니다.

기능은 이것 하나뿐입니다.

## 사용 방법

1. GitHub **Actions → 최근 빌드 → Artifacts → `NetSwitch`** 에서 `NetSwitch.exe` 를 내려받아
   아무 폴더(예: `C:\Tools\NetSwitch\`)에 둡니다. 설치는 없습니다.
   태그(`v*`)를 올리면 **Releases** 에도 exe 가 올라갑니다.
2. `NetSwitch.exe` 를 실행합니다. **처음 한 번만** UAC(관리자 권한) 창이 뜹니다.
   이때 Windows 작업 스케줄러에 "로그온 시 관리자 권한으로 실행" 작업이 등록되므로
   이후에는 윈도우가 켜질 때 자동으로 트레이에 올라오고, UAC 창은 다시 뜨지 않습니다.
3. 트레이 아이콘
   - 🔵 파란 원(와이파이 표시): **인터넷(와이파이)** 사용 중
   - 🟩 초록 사각형(랜 플러그): **업무망(유선 랜)** 사용 중
   - 🟠 주황 + `!` : 모드는 맞지만 연결이 아직 안 됨(랜선 없음, IP 대기 등)
   - 회색 화살표 깜박임: 전환 중
   - **더블클릭** → 반대쪽으로 전환 (한 번 클릭으로는 바뀌지 않음)
   - 우클릭 → 상태 보기, 전환, 자동 실행 켜기/끄기, 원래대로 복구, 로그 폴더, 종료

### 전환 순서

| 방향 | 순서 |
|---|---|
| 인터넷 → 업무망 | 와이파이 자동구성 끄기 + 연결 끊기 → 끊김 확인 → 유선 랜 어댑터 켜기 → 랜선 링크 확인 → IP 할당 확인 → DNS 캐시 비우기 |
| 업무망 → 인터넷 | 유선 랜 어댑터 끄기 → 꺼짐 확인 → 와이파이 자동구성 켜기 → 평소 쓰던 프로필로 연결 → IP 확인 → DNS 캐시 비우기 |

고정 대기시간이 아니라 실제 상태를 확인하고 다음 단계로 넘어갑니다.
보통 5~10초, 업무망에 802.1X 인증이 있으면 몇 초 더 걸립니다.

- 업무망으로 바꿨는데 **랜선이 안 꽂혀 있으면** 몇 초 기다린 뒤 자동으로 와이파이로 되돌리고 알려 줍니다.
- 업무망 모드에서 윈도우가 와이파이를 몰래 다시 붙이면 **감시 기능**이 3초 안에 다시 끊습니다(반대쪽도 동일).
- "평소 쓰던 와이파이"는 업무망으로 넘어가던 순간에 연결돼 있던 프로필을 기억했다가 그 프로필로 돌아옵니다.
  다른 프로필을 쓰려면 설정 파일의 `wifi_profile` 에 이름을 적습니다.
- 손대는 장치는 **유선 랜 어댑터 1개와 와이파이 어댑터 1개**뿐입니다. 블루투스·VPN·가상 어댑터는 건드리지 않습니다.

### 부팅 직후

어댑터 켜짐/꺼짐과 와이파이 자동구성 설정은 재부팅 후에도 유지되므로 **마지막에 쓰던 모드가 그대로 이어집니다.**
프로그램이 시작되면 저장된 모드와 실제 상태를 비교해 어긋난 쪽을 바로잡습니다.
처음 실행할 때 두 망이 모두 연결돼 있으면 지금 쓰고 있는 와이파이를 유지하고 유선 랜을 끕니다(알림으로 안내).

### 원래대로 되돌리기

업무망 모드에서는 와이파이 자동구성이 꺼져 있어 윈도우 와이파이 목록이 비어 보입니다. 이 프로그램을 더 이상 쓰지 않을 때는
우클릭 → **원래대로 복구** 를 누르거나, 명령으로 `NetSwitch.exe --restore` 를 실행하세요.
와이파이·유선 랜이 모두 켜지고 자동구성이 복구됩니다. 자동 실행 해제는 우클릭 메뉴 또는 `NetSwitch.exe --uninstall-task`.

## 설정·로그

`%LOCALAPPDATA%\NetSwitch\` (우클릭 → 로그 폴더 열기)

| 파일 | 내용 |
|---|---|
| `config.txt` | 설정. `key=value`. 프로그램을 끈 뒤 편집 |
| `netswitch.log` | 동작 기록. 문제가 생기면 이 파일을 보면 됩니다 |

주요 설정 키

| 키 | 기본값 | 설명 |
|---|---|---|
| `wifi_profile` | (비움) | 인터넷으로 돌아올 때 연결할 와이파이 프로필 이름. 비우면 마지막에 쓰던 것 |
| `wifi_method` | `autoconfig` | `autoconfig`: 자동구성 끄기+연결 끊기(빠름). `adapter`: 와이파이 장치를 통째로 끔(느리지만 가장 확실) |
| `ethernet_adapter` / `wifi_adapter` | (비움) | 어댑터가 여러 개일 때 연결 이름(예: `이더넷`) 또는 GUID 로 지정 |
| `link_wait_sec` | 12 | 유선 랜을 켠 뒤 랜선 링크를 기다리는 최대 시간 |
| `ip_wait_sec` | 25 | IP 할당을 기다리는 최대 시간 |
| `wifi_connect_wait_sec` | 20 | 와이파이 연결을 기다리는 최대 시간 |
| `watchdog` | `true` | 반대쪽 망이 몰래 다시 연결되면 자동으로 끊기 |

## 구현 메모

- C# / WinForms / **.NET Framework 4.8** (Windows 10 1903+, Windows 11 에 내장 → 런타임 설치 불필요, exe 하나 약 400 KB)
- 와이파이: Native Wifi API(`wlanapi.dll`) 직접 호출 — 자동구성(`autoconf_enabled`) 끄기/켜기, 연결 끊기, 프로필로 연결, 상태 조회.
  `netsh` 출력 파싱을 하지 않으므로 한국어 윈도우에서도 안전합니다.
- 유선 랜: WMI `root\StandardCimv2\MSFT_NetAdapter` 의 `Enable()/Disable()` (PowerShell `Disable-NetAdapter` 와 같은 경로)
- IP 확인: `System.Net.NetworkInformation` (169.254.x.x APIPA 는 미할당으로 취급)
- 권한: exe 매니페스트는 `asInvoker`. 관리자 권한은 작업 스케줄러 작업(`RunLevel=HighestAvailable`, 로그온 트리거)으로 얻습니다.
  exe 를 직접 더블클릭해도, 등록된 작업이 있으면 `schtasks /run` 으로 관리자 인스턴스를 띄우므로 UAC 가 뜨지 않습니다.
- 와이파이를 끄는 방식은 세 가지를 비교해 **"자동구성 끄기 + 연결 끊기"** 를 기본으로 택했습니다.
  라디오가 켜진 채라 재연결이 2~4초로 빠르고, 자동구성이 꺼져 있으면 윈도우가 재연결을 시도하지 않아 두 망이 겹치지 않습니다.
  실제 PC 에서 재연결이 관찰되면 `wifi_method=adapter` 로 바꾸면 됩니다(재컴파일 불필요).

## 빌드

```bash
dotnet build NetSwitch/NetSwitch.csproj -c Release
```

결과물: `NetSwitch/bin/Release/net48/NetSwitch.exe`. GitHub Actions(`.github/workflows/build.yml`)가 푸시마다 Windows 에서 빌드해 Artifact 로 올립니다.
WinForms 참조를 명시적으로 걸어 두어 리눅스의 .NET 8 SDK 에서도 컴파일 검증이 됩니다(실행은 Windows 전용).
