# NetSwitch — 랜선 꽂아 둔 채로 인터넷 ↔ 업무망 전환

노트북 한 대로 **인터넷(와이파이)** 과 **업무망(유선 랜)** 을 번갈아 쓸 때,
랜선을 뽑았다 꽂는 대신 트레이 아이콘 더블클릭 한 번으로 전환합니다.
두 망이 동시에 연결되는 순간이 생기지 않도록 **항상 쓰던 쪽을 먼저 끊고 나서 다른 쪽을 연결**합니다.

기능은 이것 하나뿐입니다.

## 설치와 첫 실행

1. GitHub **Actions → 최근 빌드 → Artifacts → `NetSwitch`** 에서 zip을 내려받아 `NetSwitch.exe`를
   로컬 폴더(예: `C:\Tools\NetSwitch\`)에 둡니다. 설치는 없습니다. 태그(`v*`)를 올리면 **Releases**에도 올라갑니다.
2. 서명이 없는 개인 도구라 Windows 보안 기능이 한 번씩 막습니다.
   - **스마트 앱 컨트롤**이 켜진 Windows 11: "안전하지 않을 수 있는 앱을 차단했습니다"가 뜨면
     설정 → 개인 정보 및 보안 → Windows 보안 → 앱 및 브라우저 컨트롤 → 스마트 앱 컨트롤 설정 → **끄기**.
     (한 번 끄면 Windows 초기화 전에는 다시 켤 수 없습니다. Defender와 SmartScreen은 그대로 동작합니다.)
   - **SmartScreen** "Windows의 PC 보호" 파란 창: **추가 정보 → 실행**. 한 번만 뜹니다.
3. `NetSwitch.exe`를 실행합니다. **처음 한 번만** UAC(관리자 권한) 창이 뜹니다.
   이때 Windows 작업 스케줄러에 "로그온 시 관리자 권한으로 실행" 작업이 등록되므로
   이후에는 Windows가 켜질 때 자동으로 트레이에 올라오고, UAC 창은 다시 뜨지 않습니다.
4. 처음 실행할 때 와이파이와 유선이 모두 연결돼 있으면 **지금 쓰는 와이파이를 유지하고 유선 랜을 끕니다**(알림으로 안내).

## 사용 방법

트레이 아이콘

| 아이콘 | 뜻 |
|---|---|
| 🔵 파란 원(와이파이 표시) | **인터넷(와이파이)** 사용 중 |
| 🟩 초록 사각형(랜 플러그) | **업무망(유선 랜)** 사용 중 |
| 🟠 주황 + `!` | 모드는 맞지만 아직 연결이 안 됨(랜선 없음, IP 대기 등) |
| 회색 화살표 깜박임 | 전환 중 |
| 회색 점 두 개 | '원래대로 복구' 상태(양쪽 모두 Windows가 관리) |

- **더블클릭** → 반대쪽으로 전환. 한 번 클릭으로는 바뀌지 않습니다.
- 우클릭 → 현재 상태, 전환, 자동 실행 켜기/끄기, 원래대로 복구, 설정·로그 폴더, 정보, 종료

### 전환 순서

| 방향 | 순서 |
|---|---|
| 인터넷 → 업무망 | 유선 어댑터 존재 확인 → 와이파이 자동구성 끄기 + 연결 끊기 → 끊김 확인 → 유선 랜 어댑터 켜기 → 랜선 링크 확인 → IP 할당 확인 → DNS 캐시 비우기 |
| 업무망 → 인터넷 | 유선 랜 어댑터 끄기 → 꺼짐 확인 → 와이파이 자동구성 켜기 → Windows 자동 연결 4초 대기 → 안 되면 평소 쓰던 프로필로 연결 → IP 확인 → DNS 캐시 비우기 |

고정 대기시간이 아니라 실제 상태를 확인하고 다음 단계로 넘어갑니다.
보통 5~10초, 업무망에 802.1X 인증이 있으면 몇 초 더 걸립니다.

- 업무망으로 바꾸는 도중 문제가 생기면(랜선 없음, 어댑터가 안 켜짐, 예외) **유선을 다시 끄고 와이파이로 되돌린 뒤** 알려 줍니다.
  어느 단계에서 실패하든 두 망이 동시에 켜진 채로 끝나지 않습니다.
- 업무망 모드에서 Windows가 와이파이를 몰래 다시 붙이면 **감시 기능**이 바로(네트워크 변경 이벤트 또는 3초 주기) 다시 끊습니다. 반대쪽도 동일합니다.
- "평소 쓰던 와이파이"는 업무망으로 넘어가던 순간에 연결돼 있던 프로필을 기억했다가 그 프로필로 돌아옵니다.
  다른 프로필을 쓰려면 설정 파일의 `wifi_profile`에 이름을 적습니다.
- 손대는 장치는 **유선 랜 어댑터 1개와 와이파이 어댑터 1개**뿐입니다. 블루투스·VPN·가상 어댑터·USB 테더링은 후보에서 제외합니다.
- 독(USB-C)이나 USB 랜 어댑터를 빼고 부팅해도 앱은 정상 동작하며, 어댑터가 다시 꽂히면 자동으로 인식합니다.
  업무망 모드로 저장돼 있었는데 유선 어댑터가 없으면 인터넷(와이파이) 모드로 시작합니다.

### 부팅 직후

어댑터 켜짐/꺼짐 상태는 재부팅 후에도 유지됩니다. 와이파이 자동구성 설정도 유지되는 것으로 알려져 있으나
Microsoft 문서에 명시돼 있지 않아, 프로그램이 시작되면 저장된 모드와 실제 상태를 비교해 어긋난 쪽을 즉시 바로잡습니다.
업무망 모드로 재부팅한 뒤 로그에 `시작: 업무망 모드인데 와이파이가 연결됨 -> 끊음`이 찍힌다면 이 PC에서는 설정이 유지되지 않는 것이니
`config.txt`에서 `wifi_method=adapter`로 바꾸면 부팅 중에도 와이파이가 올라오지 않습니다.

### 원래대로 되돌리기 / 그만 쓰기

업무망 모드에서는 와이파이 자동구성이 꺼져 있어 Windows 와이파이 목록이 비어 보입니다. 이 프로그램을 더 이상 쓰지 않을 때는
우클릭 → **원래대로 복구**를 누르세요. 와이파이·유선 랜이 모두 켜지고 자동구성이 복구되며, 다시 더블클릭할 때까지 아무것도 강제하지 않습니다.
트레이 앱이 떠 있지 않을 때는 명령으로 `NetSwitch.exe --restore`를 실행합니다(떠 있으면 먼저 종료하라고 안내합니다).
자동 실행 해제는 우클릭 메뉴 또는 `NetSwitch.exe --uninstall-task`. 해제한 선택은 설정 파일에 기억되어 다시 실행해도 되살아나지 않습니다.

## 설정·로그

`%LOCALAPPDATA%\NetSwitch\` (우클릭 → 설정·로그 폴더 열기)

| 파일 | 내용 |
|---|---|
| `config.txt` | 설정. `key=value`. 프로그램을 끈 뒤 편집 |
| `netswitch.log` | 동작 기록. 문제가 생기면 이 파일을 보면 됩니다 |

| 키 | 기본값 | 설명 |
|---|---|---|
| `wifi_profile` | (비움) | 인터넷으로 돌아올 때 연결할 와이파이 프로필 이름. 비우면 마지막에 쓰던 것 |
| `wifi_method` | `autoconfig` | `autoconfig`: 자동구성 끄기+연결 끊기(빠름). `adapter`: 와이파이 장치를 통째로 끔(느리지만 가장 확실) |
| `ethernet_adapter` / `wifi_adapter` | (비움) | 어댑터가 여러 개일 때 연결 이름(예: `이더넷`) 또는 GUID로 지정 |
| `link_wait_sec` | 12 | 유선 랜을 켠 뒤 랜선 링크를 기다리는 최대 시간 |
| `ip_wait_sec` | 25 | IP 할당을 기다리는 최대 시간 |
| `wifi_connect_wait_sec` | 20 | 와이파이 연결을 기다리는 최대 시간 |
| `watchdog` | `true` | 반대쪽 망이 몰래 다시 연결되면 자동으로 끊기 |
| `flush_dns` | `true` | 전환 후 DNS 캐시 비우기 |
| `autostart` | `true` | Windows 시작 시 자동 실행 유지 |

## 구현 메모

- C# / WinForms / **.NET Framework 4.8** (Windows 10 1903+, Windows 11에 내장 → 런타임 설치 불필요, exe 하나)
- 와이파이: Native Wifi API(`wlanapi.dll`) 직접 호출 — 자동구성(`autoconf_enabled`) 끄기/켜기, 연결 끊기, 프로필로 연결, 상태 조회.
  `netsh` 출력 파싱을 하지 않으므로 한국어 Windows에서도 안전합니다.
  자동구성을 끄는 것만으로는 현재 연결이 끊기지 않으므로 명시적으로 끊고 확인하며, 설정이 거부되거나 연결이 유지되면 어댑터를 꺼서 겹침을 막습니다.
- 유선 랜: WMI `root\StandardCimv2\MSFT_NetAdapter`의 `Enable()/Disable()` (PowerShell `Disable-NetAdapter`와 같은 경로). 비동기이므로 상태를 폴링해 확인합니다.
- IP 확인: `System.Net.NetworkInformation` (169.254.x.x APIPA는 미할당으로 취급)
- 권한: exe 매니페스트는 `asInvoker`. 관리자 권한은 작업 스케줄러 작업(`RunLevel=HighestAvailable`, 로그온 트리거, 작업 스케줄러 COM API로 등록)으로 얻습니다.
  exe를 직접 더블클릭해도, 등록된 작업이 있으면 그 작업으로 관리자 인스턴스를 띄우므로 UAC가 뜨지 않습니다.
- 관리자 프로세스는 탐색기의 `TaskbarCreated` 알림을 UIPI 때문에 받지 못하므로 메시지 필터를 등록하고, 로그온 직후에는 작업 표시줄이 생길 때까지 아이콘 표시를 미룹니다.
- Windows 11 24H2부터 위치 권한이 꺼져 있으면 연결된 SSID 이름을 읽지 못합니다. 이 경우 상태는 정상 표시되고, 돌아올 와이파이는 저장된 프로필 목록의 첫 번째를 씁니다.

## 빌드

```bash
dotnet build NetSwitch/NetSwitch.csproj -c Release
```

결과물: `NetSwitch/bin/Release/net48/NetSwitch.exe`. GitHub Actions(`.github/workflows/build.yml`)가 푸시마다 Windows에서 빌드해 Artifact로 올리고, `v*` 태그에서는 태그 번호를 버전으로 넣어 Release를 만듭니다.
WinForms 참조를 명시적으로 걸어 두어 리눅스의 .NET 8 SDK에서도 컴파일 검증이 됩니다(실행은 Windows 전용).
